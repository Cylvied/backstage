# 组长意见书（Claude）

## 1. 一句话定位

**一个安静的幕后编剧**：每轮正文写完后，在后台用一个独立的模型想一想"镜头外发生了什么"，下一轮只给正文模型递一张很短的小纸条。用户想规划剧情时，再和它商量。

## 2. 核心想法：功能 1 和功能 2 用同一套数据

参考项目的通病是每个功能各有一套数据（账本、事件线、大纲、方案、npc_track……），互相看不见，最后靠"联动"去补。我建议只有两种东西：

| 数据 | 内容 | 谁来写 |
|---|---|---|
| **人物**（镜头外的重要角色） | 在哪、在做什么、想要什么、知道什么 | 推演自动维护，用户可以改 |
| **线**（暗线、伏笔、剧情规划） | 一句话描述、当前进展、下一步、可见性（主角知不知道）、来源 | 推演自动维护；**剧情规划 = 用户和 AI 一起写的一条线** |

这样：

- **功能 1（后台推演）**：每轮推进所有人物和线。
- **功能 2（剧情规划）**：用户发起讨论 → AI 给 2–3 张方案卡 → 采纳后就是一条"来源=用户、带强度"的线。推演会照常推进它，不需要另做一套引导系统，也就不会出现故事神谕和数据库"各说各话"的问题。
- **注入**：从人物和线里挑出这一轮最相关的 1–3 条，写成一张几百字以内的"幕后小纸条"。

## 3. 一轮对话的流程

```
AI 回复第 N 楼完成
  └─ 后台调用 1 次模型（独立连接，不阻塞用户）
       输入：上一份状态 + 最近几楼正文 + 相关世界书
       输出：状态变更 + 下一轮的小纸条
  └─ 保存到"第 N 楼的当前 swipe"上

用户发送第 N+1 楼
  └─ 生成前，取"最近一楼 AI 消息的当前 swipe"上的小纸条注入
```

- 每轮**固定最多 1 次**后台调用。剧情规划只在用户点按钮时才调用。
- **状态跟着 swipe 走**：重 roll 第 N+1 楼时，用的还是第 N 楼的状态，天然正确；重 roll 第 N 楼，会退回第 N−1 楼的状态，等新回复写完再重新推演。删楼、切聊天都不用特殊处理。这条是为了根治世界引擎那一大堆重 roll 的 bug。
- 用户发得太快、推演还没跑完时：先用上一份状态，界面上标注"推演落后一轮"，绝不阻塞发送。

## 4. 第一版做什么、不做什么

**做：**

1. 每轮自动后台推演，状态绑定到楼层和 swipe。
2. 注入小纸条（位置和深度可以调）。
3. 一个面板：看和改人物、线，以及"规划剧情"按钮（方案卡 → 采纳 / 放弃）。

**不做：**

- 世界时钟、局势数值、传闻系统、多代理协作（格林推演那套）。
- 日程、日历、大纲、小剧场、局外聊天（构画那套）。
- 记忆总结和召回（交给 ST 自带功能或其他插件）。
- 剧情导演，也就是正文前的预生成（见第 5 节）。

## 5. 剧情导演（功能 3）

**建议第一版不做。** 理由：

- 它要在正文**之前**同步跑，每轮都让用户多等一次，而且要给模型更多上下文，成本最高。
- 缝合怪预设的价值，大部分其实来自它的写作规则（认知边界、不极端化情绪、角色有自己的生活），而不是"多跑一次"这个结构。这些规则可以直接写进推演提示词和小纸条里。
- 等第一版稳定后，可以加一个"导演模式"开关：开启时把后台推演从"回复后"挪到"发送前"、同步执行，并输出更详细的行动指令。数据结构不用变。

## 6. 推演提示词的原则（草案）

1. 镜头外的人有自己的生活，不是为主角而存在。
2. 认知边界：角色只知道自己见过或听说过的事。
3. 不替用户（主角）决定任何行动、想法或台词。
4. 不强行制造冲突或"关键时刻"，大多数轮次里镜头外只是小变化。
5. 小纸条只写"可能自然出现的迹象"，不让正文直接点破暗线。
6. 用户的行动永远优先：剧情偏离规划时，规划去适应剧情。

## 7. 共同问题

- **Q1**：后台推演（绑定 swipe）、小纸条注入、人物/线面板加规划按钮。
- **Q2**：不做世界数值和多代理，不做日程大纲，不做记忆系统。
- **Q3**：最多 1 次，在 AI 回复完成后异步调用；规划只在用户主动发起时调用。
- **Q4**：一个状态指示（推演中 / 完成 / 落后），一个面板（人物、线、本轮小纸条），一个规划按钮。
- **Q5**：（组长不答）
