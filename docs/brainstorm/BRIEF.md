# 头脑风暴任务书（第 1 轮）

> 发布人：Claude（组长） · 2026-10-30
> 本轮**只讨论、不写代码**。产出物是一份 Markdown 意见书。

## 0. 背景

我们要为 **TauriTavern**（SillyTavern 的 Tauri/Rust 重写版，兼容 ST 第三方扩展）写一个**后台推演插件**。

用户想要的功能：

1. **后台人物与暗线推演**：镜头外的角色在做什么、想什么，暗线和伏笔怎么发展。
2. **剧情规划**：类似"故事神谕"的剧情参谋，规划接下来剧情往哪走。
3. **剧情导演**（可选，可以不做）：类似附件"缝合怪预设"，每轮正文生成前先产出角色行动、场景和记忆召回，再交给正文模型。

用户的原话：**"不是要把几个插件缝合在一起，功能不是越多越好。"** 参考项目的功能用户都不满意，所以我们自己写。请把这句话当成本轮最重要的评判标准。

组长初读后的印象（供参考，欢迎反驳）：

- **格林推演**：思路最完整，但非常重：7 个代理、8 个账本模块、SQL 投影，一轮推演成本很高，用户很难看懂它在干什么。
- **世界引擎**：每轮对话后用独立 API 推演一份世界状态 JSON 再注入。大量 bug 出在**重 roll / swipe / 切换聊天时状态对不上**。
- **构画**：日程、事件线、大纲、小剧场、局外聊天……功能面太宽。
- **故事神谕**：剧情参谋的"方案卡 → 强度 → 悄悄注入 → 完成/放弃"交互很好，但它只是一个大工具箱里的一个模式。
- **缝合怪预设**：本质是"正文前先跑一次导演"，并且把人物追踪（npc_track）、主线支线（dm_story）都塞进同一次输出里，每轮都很贵。

## 2. 分工：每人一个角度

### Codex：技术可行性与架构

请回答：

1. **宿主接入点**：在 TauriTavern 里，扩展怎么做到以下几件事？请给出具体 API 或事件名，并写明出处（文件路径 + 行号）。
   - 监听"AI 回复完成"、"用户发送"、"重 roll / 新 swipe"、"删除楼层"、"切换聊天"。
   - 用**独立的模型连接**在后台调用 LLM，不占用主聊天生成（ST 原生的 generateRaw / generateQuietPrompt？TauriTavern 的 api.agent / llmConnections？自己 fetch？各自的利弊）。
   - 往主聊天的提示词里注入一段文本（setExtensionPrompt？generate_interceptor？其他？），以及能控制的位置和深度。
   - 存储：数据跟着聊天走、跟着 swipe 走、全局设置，各用什么（chat_metadata / api.chat 的 metadata 和 store / message.extra / api.extension.store / api.db）。
2. **状态一致性**：推演结果要和具体某一楼、某一个 swipe 绑定，用户重 roll、切 swipe、删楼、切聊天时状态才能对得上。请参考世界引擎的踩坑文档，提出你认为**最简单且可靠**的方案。
3. **架构草图**：模块划分（不超过 6 个模块），每个模块一句话职责，模块之间传什么数据。
4. **技术选型**：纯 JS 还是 TS + 构建？要不要框架做 UI？给出理由。理由要服务于"简单、好维护、三个 AI 能并行开发"。
5. **风险清单**：你预见的 3–5 个最大技术风险。
