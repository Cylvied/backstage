## 3. 技术方向（Codex 提出，组长采纳）

- **独立模型调用**：用宿主的 `ConnectionManagerRequestService.sendRequest`，让用户在连接管理器里选一个专门的连接（可以是便宜的模型）。不用 `generateQuietPrompt`（它会走主聊天的生成流程）。已核实接口存在：`refs/TauriTavern/src/scripts/extensions/shared.js:287`。
- **注入**：`setExtensionPrompt`，默认放在聊天内、深度 1、系统角色。已核实：`refs/TauriTavern/src/script.js:10479`。
- **事件**：回复完成用 `MESSAGE_RECEIVED` + `GENERATION_ENDED` 去重，排除流式中间消息、取消和失败。
- **技术栈**：TypeScript + 轻量构建 + 原生 DOM，不用 UI 框架。
- **模块（5 个）**：宿主适配、状态仓库、调度器、推演器、面板与注入。

## 4. 需要用户拍板的问题

1. **剧情导演**：三方一致建议第一版不做，同意吗？
2. **默认注入强度**：

# 第 2 轮：用户拍板的决定（2026-10-30）

用户主要用 **Gemini** 写正文。以下决定已定稿，写进 `docs/INTERFACES.md`：

1. **剧情导演第一版不做**。以后要做，就作为推演的附加输出，不增加调用次数。
2. **注入位置**：
   - 不写进 AI 回复楼，默认也不改用户输入。
   - 用 `setExtensionPrompt` 在聊天内**深度 1**注入（在最新 AI 回复之后、用户输入之前）。宿主发往 Gemini 时，聊天中间的系统消息会变成一个**独立的 user 回合**（`refs/TauriTavern/src-tauri/.../payload/makersuite.rs:370-390, 478`），所以需要用标签明确标注"幕后备注，不是主角的发言"。
3. **暗流和引导分成两块**：
   - **暗流**：深度 1，轻，写明"不必兑现"。按相关性挑选，**每层 0–3 条**（上限可调）；"暗流"语态最多 1 条；主角无法接触外界时不出"风闻"；和眼前剧情无关时允许 0 条。
   - **引导**：用户采纳的剧情规划。默认深度 1，排在暗流之后；强度为"尽快引爆"时，挪到**深度 0**（用户输入之后）。
4. **人物**：不单独做"人物谱"模块，从格林推演人物谱借 3 点：行动分"当前"和"长期"两栏、记录主角处境（位置 + 能否接触外界）、认知每轮整体重写且最多 5 条。人物上限默认 12 人，用户可以钉住或移除。
5. **记忆来源**（可选，默认关）：读数据库插件导出到世界书的纪要条目（名字形如 `TavernDB-ACU-CustomExport-纪要-N`），按关键词打分挑 6–8 条，**不调用模型**。只用作推演和规划的输入，不注入正文。用户已确认数据库纪要默认存在世界书里。
