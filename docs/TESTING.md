# 真机测试清单

> 插件版本 0.1.0（v1.5 A 批 + B 批） · 更新安装：在项目目录运行 `sh scripts/install.sh`，然后刷新 TauriTavern。
> 发现问题时，告诉组长：哪一项、做了什么、看到什么（附面板截图最好）。

## 已验证 ✓

- [x] 插件加载，魔杖菜单出现「幕后」
- [x] 面板设置里直填 API、获取模型、测试连接
- [x] AI 回复后自动推演，面板状态正常变化
- [x] 纸条里的迹象都来自暗线或不在场人物，并标注来源

## 待验证

### 1. 重 roll 与切 swipe（最容易出错）
- [ ] 重 roll 后会根据新回复重新推演
- [ ] 切回旧 swipe：暗线、人物、纸条立即变回那个 swipe 的版本，**不重新推演**
- [ ] 两个 swipe 的楼层角标都正确
- [ ] 删除最后一条 AI 回复后，面板退回上一楼的状态
- [ ] 编辑 AI 回复的正文后，该楼角标显示"已失效"，可以手动「立即推演」

### 2. 注入位置
- [ ] 在 TauriTavern 的模型请求日志里，找到发给正文模型的请求：幕后备注应在**最新 AI 回复之后、你这轮输入之前**，是一条单独的消息，以「〔幕后备注｜」开头
- [ ] 纸条页显示的内容和请求里实际注入的一致
- [ ] 关闭「注入暗流」后，请求里不再有幕后备注

### 3. 参谋对话
- [ ] 多轮讨论，参谋能说出具体的人物和暗线
- [ ] 要方案时回复下方出现方案卡，采纳后「暗线」页出现带引导的线
- [ ] 采纳后下一轮的请求里有「〔剧情引导｜」块
- [ ] 切换聊天后参谋对话是另一份，切回来记录还在
- [ ] 失败时「重试」可用，且不会重复出现同一条你的消息

### 4. 分阶段引导
- [ ] 让参谋"把这段剧情排成几个阶段"，出现分阶段方案卡
- [ ] 采纳后注入里只出现**当前这一拍**，不提后面的拍
- [ ] 演完一拍后，暗线卡上出现"这一拍看起来已经演完了"的提示（不会自动换拍）
- [ ] 「完成这一拍」后进入下一拍；跳过待演的拍；最后一拍完成后引导结束
- [ ] 「找参谋改改」重新采纳后，已演完的拍保留

### 5. 和其他插件同时使用
- [ ] 数据库插件同时开启时，两者都正常
- [ ] 开启「读取数据库纪要」后推演正常（纪要只用于推演，不注入正文）
- [ ] 故事神谕的引导与本插件的引导不要同时开（会互相干扰）

### 6. v1.5 B 批：世界模型
- [ ] **大事记**：「暗线与大事」页顶部出现镜头外已发生的事，带"第 N 天"和"主角已知 / 尚不知道"
- [ ] **镜头外的事能完成**：过了足够的故事时间后，人物的长期行动会标为完成，并在大事记里留下结果
- [ ] **时间只进不退**：人物行动下方显示"始于第 N 天，至今已过 N 天"；正文时间没动的几轮里，镜头外变化很小
- [ ] **主角得知**：正文里主角听说或看到某件事后，大事记里那件事变成"主角已知"
- [ ] **纸条**：来自未知事件的迹象标着「已发生」；正文里主角不会凭空知道这些事
- [ ] **世界书**：纸条页底部"本轮推演读了哪些资料"按四层列出；没在正文出现、但在幕后被追踪的人物，他的设定条目出现在"幕后相关"里
- [ ] **预算与常驻**：面板设置里调世界书预算（1–30 万），勾选"推演专用常驻条目"后，下一轮出现在"推演常驻"组
- [ ] **审核**：纸条页底部"本轮检查与审核"显示送审 / 通过 / 丢弃条数和原因；关闭审核后不再多一次调用
- [ ] **单独的审核模型**：审核选"单独直填"并配好后能正常工作
- [ ] 耗时与费用：有高风险改动的轮次多一次审核调用，是否可以接受

## 使用中留意

- 推演用的模型每轮多花一次调用，留意耗时和费用是否可接受
- 暗线和人物是否越来越多、越来越乱（人物上限默认 12）
- 注入的迹象会不会让正文"每轮都在暗示"，太吵就把每层暗流上限调成 1 或 0
